# Tech lead checklist

Not a personality test. Either the foundations exist or they don't.

Score each line yes/no. Three or more "no"s means you do not need a new tool. You need defaults.

- [ ] We have a written definition of done, and people use it.
- [ ] Pull requests are reviewed by someone other than the author, most of the time.
- [ ] At least two people can release.
- [ ] We can name who owns deploy, CI, and "production is down".
- [ ] CI runs on pull requests and we would notice if it went red.
- [ ] A new person could ship a small change in week one without a two-day download from the lead.
- [ ] Work in progress is visible, not trapped in private branches and DMs.
- [ ] The tech lead is **not** the default reviewer / releaser / firefighter.
- [ ] We have killed or simplified a rule in the last quarter — or looked and nothing deserved to die.
- [ ] When production misbehaves, there is a default path that isn't "message the lead and hope".

## If you are new to the role

Days 1–30: notice how work actually happens. Do not introduce five processes.

Days 31–60: install a Definition of Done, a PR template, and CI. Measure.

Days 61–90: automate one painful thing. Kill one useless thing. Someone other than you should have released.
